# Tech Opportunity Tracker — Work Plan

## Project Objective

Build a responsive web application that helps users discover, search, filter, and save technology opportunities.

## Week 1 — Foundation and Core Interface

### Planned Tasks
- Set up the React and Vite project.
- Create the main application interface.
- Display opportunity cards using sample data.
- Implement keyword search and category filtering.
- Implement save and unsave interactions.
- Add empty-results feedback and a clear-filters action.
- Improve mobile responsiveness and basic accessibility.
- Prepare project documentation.
- Publish the code in a public GitHub repository.
- Deploy the application and capture mobile and desktop screenshots.
- Prepare the Week 1 report and five-minute presentation.

### Deliverables
- Working responsive interface
- Public repository with README
- Idea one-pager and work plan
- Deployment link and screenshots
- Week 1 Git tag and weekly report

## Week 2 — Data Integration and Improved Components

### Planned Tasks
- Organise the interface into reusable React components.
- Integrate a public API, mock service, or developer-created backend.
- Implement asynchronous data loading.
- Add loading, empty, error, and retry states.
- Improve search and filtering using the integrated data.
- Record at least five issues or implementation challenges.
- Update the README and publish the Week 2 version.

### Deliverables
- Reusable component structure
- Working data integration
- Loading and error handling
- Issue log
- Updated deployment and `week-2` Git tag

## Week 3 — Routing, Testing, and Accessibility

### Planned Tasks
- Add at least two routed views.
- Support direct links and a not-found page.
- Persist saved opportunities across views and, where appropriate, page reloads.
- Conduct an accessibility audit and record improvements.
- Test the application using keyboard-only navigation.
- Write and run at least three automated tests.
- Update the README, deployment, and project evidence.
- Prepare the final walkthrough and reflection.
- Document the use of AI assistance and external sources.

### Deliverables
- Routed application
- Persistent saved-opportunity feature
- Automated tests
- Accessibility audit and before-and-after record
- Final deployment and `week-3` Git tag
- Final report, reflection, and five-minute walkthrough

## Risks and Mitigation

- **Unavailable or unreliable opportunity data:** Use clearly labelled sample data until a suitable data source is integrated.
- **Mobile layout problems:** Test at narrow mobile widths and desktop sizes.
- **Accessibility issues:** Check keyboard navigation, focus visibility, contrast, and semantic structure.
- **Time constraints:** Prioritise required features before optional enhancements.

## Progress Tracking

Tasks will be marked complete only after implementation and verification. Repository links, deployment links, screenshots, test results, and reports will be added as they become available.
